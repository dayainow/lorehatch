# 제품 흐름과 MVP

## 고객과 핵심 가치

초기 고객 가설: 컴퓨터에서 오래 작업하는 크리에이터·개발자·학생 중 생물 수집을 좋아하는 사람. ‘집중력을 높인다’는 효능은 아직 검증하지 않았다. 약속은 조용한 동반과 발견이다.

AI 사용자를 홍보 채널로 시험할 수 있지만 AI 토큰 소비가 필수인 제품은 아니다. 도감 완성을 위해 비용을 쓰게 하거나 밤샘을 유도하지 않는다.

## 첫 10분 — 설계 목표, 미검증

- 0~1분: 이름 없이도 이해되는 보호구역 장면. 가지숲/습지 선택.
- 1~3분: 흔적을 눌러 첫 환수와 확정적으로 만남. 계정 가입·결제 없음.
- 3~4분: 별명 선택(선택 사항), 첫 행동 관찰, 도감 1페이지 획득.
- 이후: 10/25/50분 중 사용자가 세션을 고르거나 짧은 체험을 진행. 시간 제한은 집중의 평가가 아니라 탐방 진행 방식.
- 세션 종료: 짧은 탐방 보고서와 다음 만남의 단서. 작업 중 팝업으로 주의를 빼앗지 않음.

## 반복 흐름

동료/지역 선택 → 집중 세션 → 흔적 받기 → 관찰 과제 선택 → 확정적 맞이하기 → 돌봄과 행동 발견 → 도감 기록 → 새로운 길.

유료 랜덤 알, 환수 죽음, 미접속 벌점, 연속 출석 초기화, 강제 야간 접속을 넣지 않는다. 중복 환수는 판매 재화로 갈아버리기보다 선택적으로 별도 개체로 맞거나 흔적을 다른 탐방에 사용한다. 첫 MVP는 중복 없이 수집 경로를 단순화한다.

## 게임 규칙의 초기 가설

- 첫 환수는 즉시, 두 번째는 2~3개 짧은 세션 안에 만나도록 튜닝.
- 성장 기준은 세션 수 + 돌봄 선택. 토큰 수·마우스 이동량·실제 문서 내용과 무관.
- 일일 보상 상한을 두되 상한 뒤에도 관찰·꾸미기를 즐길 수 있음. 초기 후보: 보상 세션 4회/일, 테스트 후 변경.
- 내부 환경 시간은 사용자가 선택. 밤에만 나오는 환수로 현실 야간 접속을 강요하지 않음.
- 세션 중 일시정지/수면을 명시적으로 처리하고, 오프라인 복귀 보상은 한 번만 정산. 반복 재실행 악용은 기능 테스트에서 검증.

## 화면

1. 메뉴바: 동료·세션 상태·열기.
2. 작은 데스크톱 동료 창: 조용한 대기/잠, 드래그, 숨기기, 동작 줄이기.
3. 보호구역: 지역 탭, 환수 선택, 장식 소수.
4. 관찰 도감: 종 목록, 개체, 전승/창작/관찰 탭.
5. 탐방 보고서: 이번 발견과 다음 조건.
6. 설정: 소리·알림·크기·자동 시작·데이터 내보내기/삭제.

## 플랫폼 결정

macOS를 1차 대상으로 추천. React+TypeScript 공통 UI와 Tauri 호스트를 후보로 두되 tray, 투명 창, Spaces/전체화면, 접근성, 전력 소모를 작은 실험으로 검증한 뒤 확정한다. Web/Chrome 공통화는 데이터와 화면부터 하고 네이티브 기능은 어댑터로 분리.

Chrome 확장은 새 탭/사이드패널 동료 버전으로 후속 검토. 페이지 위 오버레이와 광범위한 사이트 권한은 처음부터 요구하지 않는다. macOS와 Chrome을 동시에 완성하려 하지 않는다.

## 데이터와 개인정보

기본은 로컬 저장. 캐릭터 상태·설정·세션 시간·도감만 저장하고 작업 내용, 키 입력, URL, 클립보드, AI 인증 토큰은 수집하지 않는다. 계정·서버·분석 SDK는 MVP 필수가 아니다. 테스트 데이터 공유는 명시적 동의와 필요한 최소 항목으로 별도 설계.

도감 콘텐츠는 버전이 있는 정적 JSON. 출처와 창작 설정을 필드로 분리. 세이브에는 콘텐츠 ID를 참조하고 구 버전 마이그레이션을 설계. 이 저장소의 JSON은 콘텐츠 초안이며 제품의 완성된 세이브 규격은 아니다.

## MVP 밖

전투, PvP, 교배, 거래, 클라우드 동기화, 여러 사용자 방문, 실시간 AI 대화, 자동 생성 도감, 유료 결제, AI CLI 로그 연결. 이후에도 브랜드 가치·유지 비용을 검증하고 채택한다.
